# tracks

Repo-agnostic workstream tracks for Pi.

## What it does

The `tracks` extension manages standardized workspaces under `.pi/tracks/<slug>/`.
Each track gets a local `AGENTS.md`, durable markdown files for ongoing workstream state,
and a machine-readable `track.yaml`.

A track is intended to stay open across multiple sessions and milestones while the same
initiative is still active. Finishing one subtask or implementation pass does not imply
that the track should be closed.

`/track use <name>` attaches the current session to a track and also records the
most recent project-level selection in `.pi/tracks/settings.json`. Runtime behavior
for an already-running session follows the session trace entry, not the repo settings
file, so parallel Pi sessions do not steal each other's context or shutdown sync target.
When a track is attached to the current session, Pi injects only the local `AGENTS.md`
and `summary.md` before agent execution. On session shutdown, the extension performs a
best-effort `/track sync` for that attached session track.

## Commands

- `/track list`
- `/track new <name> --purpose "..." [--activate]`
- `/track use <name>`
- `/track status [name]`
- `/track sync [name]`
- `/track end [name]` — close a track only when the broader workstream is actually done, abandoned, or superseded

## Generated workspace

```text
.pi/tracks/
  settings.json
  <track-slug>/
    AGENTS.md
    track.yaml
    summary.md
    tasks.md
    references.md
    findings.md
    decisions.md
    report.md
    notes/
    artifacts/
```

## Behavior notes

- The extension manages only `.pi/tracks/` plus session trace entries.
- Tracks are ongoing initiative/workstream contexts, not one-shot task folders.
- `summary.md` is deterministic and regenerated by `/track sync`.
- `report.md` is a live artifact. Keep it current during work, then finalize it with `/track end` when the broader track is truly finished.
- Missing template-backed files can be regenerated during sync.
- Closing a track does not automate promotion into repository docs, issue trackers, or any other system.
